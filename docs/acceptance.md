# 验收标准

| 检查 | 通过条件 |
| --- | --- |
| 两设备读同一事实 | 两个独立克隆刷新后，对同一记录返回同一 SHA 和内容。 |
| 提案待审 | 只推 proposal 分支时，读取设备仍返回原状态，`verify` 返回 3。 |
| 审阅合并 | 冻结 diff 有明确 reviewer、证据与审批结果，PR 仅包含预期变更。 |
| 发布读回与重试 | 合入上游后，独立克隆 `verify` 成功。用同一候选重试返回 `already-published`。 |
| 断网及冲突 | 缓存有 SHA 和新鲜度标签，断网仍能制备候选。上线后同一记录变更会触发冲突，另一条记录的变更不阻塞。 |
| 只读与鉴权 | 只列出两个只读工具。越权 ID、未认证 HTTP 请求和伪造 Host 被拒。 |
| 客户端接通 | 每个真实 Agent 在新会话调用工具或只读 GitHub 连接器，返回合成记录的真实 SHA。登记客户端、版本、读取范围和复测结果。 |
| 远程路由和回退 | 从另一网络验收 TLS、有效凭据、缺失凭据和撤销结果，确认主机重启后能恢复服务。 |
| 设备直连与 DevSpace | 从指定发起设备核验目标系统、主机名和获准操作。DevSpace 分别读取各设备的合成标记并拒绝白名单外测试路径。按[设备远控和 DevSpace](devices.md)记录 SSH、桌面和 MCP 各自的验收结果。 |

本仓库测试覆盖 Git 读回、待审分支、离线与同记录冲突、其他记录并行修改、候选篡改、stdio MCP、回环 HTTP MCP。测试在临时 Git 上游完成。GitHub PR 权限、真实 Windows/Mac 客户端、Muse、DeepSeek、Kimi、Antigravity，以及真实域名和隧道均由每个部署独立验收。CI 定义提供 Linux、macOS、Windows 的运行入口，实际运行状态看目标仓库的 Actions。

## 维护者发布检查

在新仓库里只放本公开模板的文件。检查 Git 暂存清单、完整 diff 和历史提交，运行凭据扫描，并人工确认内容仅含示例路径、示例账号、合成记录和可公开说明。以干净克隆运行 README 测试。发布后用公开地址确认可见性、目标 commit 和文件树，并登记尚未验证的真实客户端。已有私有仓库的改可见性不适合作为发布路径。

发布前用公开克隆检查 Git 作者和提交者邮箱，使用 GitHub 提供的 noreply 地址或项目公开身份。同步检查公开的 CI 运行元数据。安装程序和运行时依赖都要进行独立审计，记录上游组件的已知限制。

## 自动化适配器的额外验收

以下要求适用于部署方另行接入的生命周期 Hook、定时任务、模型诊断或通知适配器。Shared Facts 本身不因此增加常驻调度、模型调用、自动修复或通知服务；发布记录仍以指定分支和独立设备读回为准。

| 检查 | 通过条件 |
| --- | --- |
| 真实触发 | 分别记录配置检查、合成测试与真实客户端或计划任务触发的证据；前两项不能替代后一项。 |
| 分阶段完成 | 执行结果、持久写回、审阅合并、发布读回各自记录状态。执行器退出成功不能代替写回或发布完成。 |
| 写回失败可恢复 | 已验证结果在调用下游写回前先原子保存，绑定内容哈希和任务归属；重启后能恢复完整结果。写回被拒时保持阻塞，不能靠重新调用模型或重复副作用掩盖失败。 |
| 容量与预算 | 启动新工作前检查容量、并发及重试预算。容量满时拒绝新增工作，已发布记录的读取继续；新任务或新会话不能重置整条链路的预算。 |
| 未知结果 | 中断后的结果未知时先对账；不因等待时间长而自动重做、删除待审材料或释放仍有归属的执行状态。 |
| 缓存回收 | 仅在下游完整结果已读回确认后回收缓存，删除前再校验实际字节哈希及归属。被改动文件、未知条目和未写回材料保留并报告，不按年龄批删。 |

验收应包含下游写入被拒、进程中断、容量耗尽、旧记录兼容和重复提交场景。能力由具体部署验证，不能把这些要求表述成尚未实现或尚未测试的产品功能。
